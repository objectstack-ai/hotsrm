## 计划补充

| 目录 | 内容 | 时机 |
|---|---|---|
| `requirements/` | 需求记录 `NNNN-*.md`：客户需求提炼成通用表述后登记，写明落在核心、扩展包还是参数 | 收到第一个新需求时 |
| `engineering/` | 元数据建模规范、测试策略、版本与升级策略 | 开始写代码前 |
| `integration/` | ERP 等外部系统的接口规格，每个数据流一份（I1–I15） | 第一期开发前（先写 I1–I6） |
| `implementation/` | 实施手册、数据导入模板、上线检查清单 | 第一个客户项目启动时 |
| `reference/` | 由元数据自动生成的对象、字段、选项、权限清单（禁止手改） | 有代码之后 |
| `../content/docs/` | 对外的产品文档、用户手册、供应商操作指南 | 临近上线 |

## 阅读方式

- 内部团队：在 GitHub 上直接阅读，Markdown 会渲染成带标题、表格、流程图的页面。
- 客户：阅读由体系文件模板和设计文档生成的 Word / PDF，不需要接触 Markdown 或 git。
