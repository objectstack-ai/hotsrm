# hotsrm 核心设计 · 需求分析与设计

> 状态：设计草案 v0.2（2026-10-23）：按 [ADR-0008](../adr/0008-order-to-pay-stays-in-erp.md)、[ADR-0009](../adr/0009-core-first-pack-criteria-and-customer-layer.md) 收窄范围并按版本重排；审核修正见各篇标注
> 适用：hotsrm 的通用核心，即在 ObjectStack（ObjectOS 元数据驱动运行时）上构建的 SRM 应用包。
> 行业差异见 [扩展包](../packs/README.md)，管理制度模板见 [体系文件](../../governance/README.md)
> 受众：产品、实施顾问、开发，以及采购 / 质量 / 财务业务方
> 约定：对象、字段、选项值等机器名用 snake_case 英文；标签、正文用中文

## 1. 一页纸结论

**定位**：SRM 负责企业**与供应商协同**的那一半——供应商全生命周期、合同、质量整改、
绩效与风险、寻源定价、供应商门户。采购订单、收货、对账、发票、付款留在 ERP
（system of record），SRM 只记结论、不做第二套账；交付与质量结果按月导入用于算分
（[ADR-0008](../adr/0008-order-to-pay-stays-in-erp.md)）。

**形态**：一个用 TypeScript 元数据定义、编译成单一制品发布的应用包 `srm`（命名空间
`srm`），核心 **27 个业务对象**，按 v0.1–v0.7 七个版本交付（[07 §1](./07-delivery-plan.md#1-分期路线图)）；
两个应用外壳——内部的「采购协同工作台」（v0.1 起）和面向外部的「供应商门户」（v0.6），
两者读写同一份数据，靠权限区分各自能看到什么。现阶段只做核心包，扩展包保留为设计（ADR-0009）。

**六个关键设计决定**：

1. **声明式优先，托管云今天就能跑**：托管云上安装的应用包只合并元数据，包里的代码
   （钩子、插件、任务函数）不执行。所以全部规则都用元数据表达——对象、校验规则、
   RLS、flow、审批。需要代码的写法只作为自托管部署的可选增强，单独标注。
2. **供应商之间零可见**：每家开通门户的供应商对应一个平台**岗位**（如
   `srm_vendor_sup0000128`，首次开通时由管理员新建），它的门户用户被任命到这个岗位；每张面向供应商的单据
   在创建时冗余该岗位标识，门户 RLS 只放行 `portal_position in current_user.positions`
   的行。解析不到岗位时策略不放行任何行（fail-closed）。详见
   [04 §3](./04-security-and-portal.md#3-供应商门户的数据隔离)。
3. **封标**：报价截止前，内部任何角色（包括 AI 助手）都读不到报价。报价上有一个
   开标时才写入的 `bid_opened` 标志，内部 RLS 只放行 `bid_opened == true` 的报价；
   截止后供应商的修改由校验规则用 `now()` 比较冗余在报价上的截止时间来拒绝，
   不依赖定时任务准时运行。详见 [03 §4](./03-processes-and-automation.md#4-p3-寻源询价--比价--定标v07)。
4. **流程就是 flow**：审批用 flow 的 `approval` 节点；单据状态是主对象上的 `select`
   字段，非法跳转由 `state_machine` 校验规则拦截；**不建**「审批记录表」，审批历史
   由平台保存且不可篡改。需要跨对象判断的写操作（邀请供应商、建送货单、提交发票）
   只开放为以系统身份运行的 `screen` flow。
5. **预留集成点，现阶段不集成 ERP**：物料和交付记录用表格导入；供应商、价格、合同上
   保留 `erp_*` 外部单号字段空着；ERP 连接器在客户明确型号时立项（[06](./06-integration-and-ai.md)）。
6. **内部优先，MVP 是内部版**：v0.1–v0.5 先做供应商生命周期、合同、质量、绩效、风险，
   20 个对象试运行通过后（门槛 1）再开门户（v0.6），然后寻源（v0.7，门槛 2：核心冻结）。

**待确认的事**：见 [07 §5 待决策事项](./07-delivery-plan.md#5-待决策事项附推荐)。原 D1–D9
大多已随 v0.1 开工采纳；2026-10-23 新增的 P-D1（审批矩阵以设计为准）、P-D2（物资 A / B / C
分类进系统）、P-D4（核心源语言：中文源、英文译）已于 2026-10-24 裁定。

## 3. 默认业务画像（设计假设）

核心设计按下面的默认画像编写。与默认画像不同的行业特征，优先用扩展包补充，其次
用参数配置，尽量不改核心（见 [扩展包](../packs/README.md)）。

| 维度 | 默认假设 | 改变后影响哪里 |
|---|---|---|
| 行业 | 离散制造（机械 / 电子 / 汽配），直接物料为主，兼顾 MRO 等间接采购 | 准入审核项、绩效指标、质量模块深度；大宗原料按批次化验计价的行业见大宗物料包，涉及危险化学品的见危化品包 |
| 规模 | 年采购额 5–50 亿元，活跃供应商 300–2000 家，采购相关内部用户 30–150 人 | 门户并发、数据量、审批层级 |
| 组织 | 1 个集团、2–5 个法人、多个工厂（收货地点） | 多法人隔离姿态（D2）、对账维度 |
| ERP | 已有 ERP（SAP / 用友 / 金蝶之一），负责物料、PO 记账、收货、应付、付款；现阶段不集成，物料与交付记录按月表格导入 | 预留集成点（06）、交付记录（02 §4.6） |
| 供应商 | 以国内供应商为主，增值税专票，用统一社会信用代码建档；境外供应商按「国家 / 地区 + 注册号」建档；全部界面中英文（[ADR-0007](../adr/0007-china-first-with-overseas-seams.md)） | 字段、发票模型、国际化 |
| 招标 | 企业自主采购，不涉及《招标投标法》意义上的依法必须招标项目 | 国有企业的采购方式、限额与监督要求见国企采购合规包；依法必须招标的项目仍需专业电子招投标平台（范围外） |

## 4. 术语表

| 术语 | 含义 |
|---|---|
| SRM | Supplier Relationship Management，供应商关系管理 |
| S2C / P2P | Source-to-Contract（寻源到合同）/ Procure-to-Pay（采购到付款） |
| 准入 | 潜在供应商经资料审核、现场审核、样品验证后成为合格供应商的过程 |
| 合格供应商名录（AVL） | Approved Vendor List，按品类记录可供货的合格供应商 |
| RFQ | Request for Quotation，询价单 |
| 封标 / 开标 | 截止前报价对采购方不可见 / 截止后统一解封报价 |
| 定标 | 确定中标供应商与份额，金额分级审批 |
| 价格库（信息记录） | 供应商 × 物料 × 有效期的协议价格，ERP 下单取价依据 |
| ASN | Advanced Shipping Notice，送货通知 / 发货单 |
| IQC | Incoming Quality Control，来料检验 |
| SCAR / 8D | Supplier Corrective Action Request，供应商纠正措施要求；8D 为整改方法 |
| OTD | On-Time Delivery，交付准时率 |
| PPM | 每百万件不良数 |
| QCDS | 质量 Quality、成本 Cost、交付 Delivery、服务 Service，绩效四维度 |
| OWD | 组织级默认可见性（private / public_read / public_read_write / controlled_by_parent） |
| RLS / FLS | 行级安全 / 字段级安全 |
| 权限集 / 岗位 | permission set（能做什么）/ position（权限集的挂载点） |
