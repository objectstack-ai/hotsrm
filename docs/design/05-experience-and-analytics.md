# 05 · 界面、分析与通知

> 所属：[SRM 设计总览](./README.md)　·　上一篇：[04 权限与门户](./04-security-and-portal.md)　·　下一篇：[06 集成与 AI](./06-integration-and-ai.md)

## 1. 两个应用外壳

同一份数据，两个应用：内部员工用「采购协同工作台」，供应商用「供应商门户」。门户
应用只对持有门户权限集的用户可见；即便有人拿到内部应用的地址，RLS 仍然只放行他
本公司的数据（应用可见性是体验，RLS 才是边界）。

### 1.1 采购协同工作台 `srm_workbench`

```
采购协同工作台
├── 首页                    我的待办 · 我负责品类的关键指标
├── 供应商
│   ├── 供应商              合格名录 / 全部 / 资质异常 / 按生命周期看板
│   ├── 准入申请            待我审核 / 进行中 / 已结束
│   ├── 供应商审核
│   ├── 资质证书            30 天内到期 / 已过期
│   └── 变更与处置          （二期）
├── 寻源
│   ├── 寻源单              我的 / 报价中 / 待开标 / 评标中 / 定标审批中
│   ├── 报价                （开标后可见）
│   ├── 价格库              当前有效 / 即将失效
│   └── 合同                （二期）
├── 订单协同                （二期）
│   ├── 采购订单            待确认 / 交期风险 / 变更待确认
│   ├── 送货单
│   └── 收货记录
├── 质量                    （三期）
│   ├── 来料检验
│   └── 整改单              看板 / 逾期
├── 结算                    （四期）
│   ├── 对账单
│   └── 发票
├── 绩效与风险              （三、四期）
│   ├── 考评单
│   └── 风险事件
├── 分析                    仪表盘（见 §4）
└── 设置                    品类 · 物料 · 工厂 · 绩效指标（管理员）
```

### 1.2 供应商门户 `srm_portal`

```
供应商门户
├── 首页              我的待办（见 01 §5.10）· 最新绩效 · 即将到期的证书
├── 公司资料          本公司档案 · 联系人 · 资质证书 · 银行账户 · 变更申请
├── 询价与报价        收到的邀请 · 我的报价（草稿 / 已提交 / 历史）
├── 订单与送货        待确认订单 · 全部订单 · 送货单
├── 质量              整改单 · 检验结果
├── 对账与发票        待确认对账单 · 发票与付款状态
└── 绩效              历次考评结果
```

门户的设计原则：**每个页面只有一个主要动作**（确认订单、提交报价、回复整改），按钮
文案直接写动作；首页待办点进去就是要处理的那条记录；不要求供应商理解内部流程状态，
门户上的状态标签用供应商视角的说法（「待您确认」而不是 `released`）。

## 2. 关键视图

平台提供的视图类型：列表（可分组）、表单、看板、日历、画廊、甘特，以及报表（表格 /
汇总 / 矩阵）。

| 对象 | 视图 | 类型 | 定义 | 主要用户 |
|---|---|---|---|---|
| 供应商 | 合格名录 | 列表 | `status == 'qualified'`，按品类分组 | 采购员 |
| 供应商 | 生命周期看板 | 看板 | 按 `status` 分列 | 品类经理 |
| 供应商 | 资质异常 | 列表 | `qualification_alert == true` | SQE |
| 准入申请 | 待我审核 | 列表 | `reviewer == 当前用户` 且未结束 | 品类经理 |
| 准入申请 | 准入进度 | 看板 | 按 `status` 分列 | 品类经理、SQE |
| 资质证书 | 即将到期 | 列表 | `status == 'expiring'`，按 `valid_to` 升序 | SQE |
| 资质证书 | 到期日历 | 日历 | 日期字段 `valid_to` | SQE |
| 寻源单 | 寻源看板 | 看板 | 按 `status` 分列 | 寻源工程师 |
| 寻源单 | 截止日历 | 日历 | 日期字段 `quote_deadline` | 寻源工程师 |
| 报价明细 | 比价表 | 列表 | 过滤到某寻源单本轮，按寻源明细分组、组内按 `unit_price` 升序 | 评标小组 |
| 报价明细 | 比价矩阵 | 矩阵报表 | 行 = 寻源明细，列 = 供应商，值 = 单价；另一块为总价与交期 | 评标小组、审批人 |
| 价格记录 | 当前有效价格 | 列表 | `status == 'active'`，按物料分组 | 采购员 |
| 采购订单 | 待供应商确认 | 列表 | `status == 'released'`，按 `released_at` 升序，显示已等待小时数 | 采购员 |
| 订单行 | 交期风险 | 列表 | `delivery_risk == true` 且未收齐 | 采购员 |
| 订单行 | 交货排程 | 甘特 | 起止为 `required_date` / `promised_date` | 计划员 |
| 整改单 | 整改看板 | 看板 | 按 `status` 分列，逾期卡片标红 | SQE |
| 对账单 | 本月对账 | 列表 | 本月生成，按 `status` 分组 | 应付会计 |
| 考评单 | 本期考评 | 列表 | 当前期间，按 `grade` 分组 | 采购总监 |

门户侧的视图是上述视图的子集，由 RLS 自动限定到本公司，**不需要**为门户单独写过滤
条件——写了也只是体验，不能替代 RLS。

## 3. 关键页面

**供应商 360 页**（内部）：页头显示编号、名称、状态、等级、资质异常标记；页签依次为
概览（基本信息 + 最近 4 期绩效 + 未关闭整改单数）、联系人、资质证书、供货品类、
银行账户（仅有权角色可见）、寻源记录、价格、订单、质量、对账、风险事件、变更历史。

**寻源单工作页**（内部）：上半部分是寻源单信息与「已邀请 N 家 / 已报价 N 家」；
下半部分在开标前显示邀请与响应状态，开标后切换为比价表与比价矩阵；页头按钮随状态
变化：发布 → 开标 → 下一轮 → 提交定标。

**订单确认页**（门户）：订单头只读；订单行表格内联编辑「答复交期 / 答复数量 / 延期
原因」，一个「确认全部」按钮处理交期与需求一致的常见情况。手机上表格折叠为卡片。

**报价页**（门户）：显示截止倒计时；明细表格内联填写单价、交期、税率；提交前汇总
总价；截止后整页只读并提示「已截止」。

## 4. 仪表盘与指标口径

### 4.1 指标口径

所有比率在**写入时**计算并存到数值字段上（平台的仪表盘求和、平均只能落在存储的
数值字段上，公式字段不行）。

| 指标 | 口径 | 数据来源（存储字段） | 计算时机 |
|---|---|---|---|
| 交付准时率 OTD | 准时收货行数 ÷ 收货行数；退货行不计；无答复交期时按需求日期判定 | 收货记录 `on_time`；考评单 `otd_rate` | 收货写入时判定，季度考评时汇总 |
| 批次合格率 | 判定为合格的检验批次 ÷ 检验批次；让步接收计为不合格 | 检验 `result`；考评单 `lot_pass_rate` | 同上 |
| PPM | 不良数 ÷ 收货数 × 1,000,000 | 检验 `defect_quantity`、收货 `received_quantity`；考评单 `ppm` | 季度考评时 |
| 订单响应及时率 | 下发后 24 小时内被确认的订单数 ÷ 下发订单数 | 订单 `released_at`、`confirmed_at`；考评单 `ack_on_time_rate` | 同上 |
| 寻源节约额 | Σ（预算价或上次价格 − 定标价）× 定标数量 | 寻源单 `savings_amount` | 定标时 |
| 线上寻源覆盖率 | 线上定标金额 ÷ 新增定价总金额（含 ERP 中手工定价） | 寻源单 `awarded_amount` + ERP 数据 | 月度 |
| 准入周期 | 准入申请从提交到批准的天数，取中位数 | 准入申请 `created_at` 与批准时间 | 批准时写 `cycle_days` |
| SCAR 按期关闭率 | 按期关闭的整改单 ÷ 到期的整改单 | 整改单 `is_overdue`、`status` | 每日扫描 |
| 采购支出 | Σ 收货金额，按供应商 / 品类 / 法人 | 收货记录 `amount`（数量 × 订单行单价，flow 写入） | 收货写入时 |
| 资质合规 | 资质异常但仍为合格状态的供应商数 | 供应商 `qualification_alert` | 每日扫描 |

### 4.2 仪表盘清单

| 仪表盘 | 读者 | 卡片 |
|---|---|---|
| 采购总览 | 采购总监、总经理 | 本年支出（按品类）、Top 10 供应商支出、寻源节约额、供应商等级分布、资质异常数 |
| 寻源 | 品类经理、寻源工程师 | 进行中寻源单（按状态）、本月定标金额、平均有效报价家数、单一来源占比 |
| 供应商 | 品类经理、SQE | 供应商按生命周期分布、30 天内到期证书数、准入申请积压、风险事件（按严重度） |
| 交付 | 采购员、计划员 | 待确认订单数、交期风险行数、按月准时 / 不准时收货行数（堆叠柱） |
| 质量 | SQE、质量经理 | 本月不合格批次、未关闭整改单（按状态）、逾期整改单、按供应商的 PPM 排名（季度） |
| 门户首页 | 供应商 | 待办计数卡片、最新等级与总分、近 4 期得分趋势 |

两个平台约束会影响卡片设计：

- **比率不在查询时现算**：月度 OTD 趋势用「准时 / 不准时」两组计数的堆叠柱表达，
  季度比率趋势读考评单上已存储的 `otd_rate`；
- **多值字段不能做分组维度**：按「供货品类」统计供应商数时，基于供货品类资格对象
  （每行一个品类）分组，而不是基于供应商上的多选字段。

另外，仪表盘在首次上线时可能因为数据太少而显示 0，建议一期上线先交付数据与视图，
跑满一个月后再启用趋势类卡片。

## 5. 通知

| 事件 | 接收人 | 通道 | 期次 |
|---|---|---|---|
| 准入申请已受理 / 已驳回 / 已通过 | 申请联系人 | 邮件 | 一期 |
| 待你审核的准入申请、待你审批的定标 | 审批人 | 站内 + 邮件 | 一期 |
| 新的询价邀请 | 受邀供应商 `sales` 联系人 | 邮件 + 门户待办 | 一期 |
| 报价截止前 24 小时仍未提交 | 受邀供应商 | 邮件 | 一期 |
| 中标 / 未中标 | 参与报价的供应商 | 邮件 | 一期 |
| 证书即将到期 / 已过期 | 供应商联系人、SQE | 邮件 + 站内 | 一期 |
| 新订单待确认、订单变更 | 供应商 `sales` 联系人 | 邮件 + 门户待办 | 二期 |
| 交期风险 | 采购员 | 站内 | 二期 |
| 订单 24 / 48 小时未确认 | 供应商 / 采购主管 | 邮件 / 站内 | 二期 |
| 新整改单、整改退回、整改逾期 | 供应商 `quality` 联系人 / SQE 主管 | 邮件 + 门户待办 | 三期 |
| 绩效结果发布 | 供应商 `admin` 联系人 | 邮件 | 三期 |
| 对账单待确认、付款完成 | 供应商 `finance` 联系人 | 邮件 + 门户待办 | 四期 |

通知模板统一放在应用包里，按中文 / 英文两套维护；邮件只给出摘要和门户链接，**不在
邮件正文里放报价金额、银行账号等敏感内容**。

## 6. 多语言与移动端

- **多语言**：对象、字段、选项、视图标签按中文维护，并为门户涉及的对象补充英文翻译；
  选项值（机器名）不随语言变化。
- **移动端**：门户的首页待办、订单确认、整改回复、对账确认在手机浏览器可完成；比价
  矩阵、供应商 360 页等内部重度页面只保证桌面端体验。
