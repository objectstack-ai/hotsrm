# 05 · 界面、分析与通知

> 所属：[SRM 设计总览](./README.md)　·　上一篇：[04 权限与门户](./04-security-and-portal.md)　·　下一篇：[06 集成与 AI](./06-integration-and-ai.md)

## 1. 两个应用外壳

同一份数据，两个应用：内部员工用「采购协同工作台」，供应商用「供应商门户」。门户
应用只对持有门户权限集的用户可见；即便有人拿到内部应用的地址，RLS 仍然只放行他
本公司的数据（应用可见性是体验，RLS 才是边界）。

### 1.2 供应商门户 `srm_portal`（v0.6）

```
供应商门户
├── 首页              我的待办（见 01 §5.10）· 最新绩效 · 即将到期的证书
├── 公司资料          本公司档案 · 联系人 · 资质证书 · 银行账户 · 变更申请 · 准入申请进度
├── 质量              整改单 · 交付结果
├── 绩效              历次考评结果
├── 询价与报价        （v0.7）收到的邀请 · 我的报价（草稿 / 已提交 / 历史）
└── 订单与付款        （ERP 集成后的门户镜像）待确认订单 · 送货单 · 付款进度
```

门户的设计原则：**每个页面只有一个主要动作**（确认订单、提交报价、回复整改），按钮
文案直接写动作；首页待办点进去就是要处理的那条记录；不要求供应商理解内部流程状态，
门户上的状态标签用供应商视角的说法（「待您确认」而不是 `released`）。

条件——写了也只是体验，不能替代 RLS。

## 3. 关键页面

**供应商 360 页**（内部）：页头显示编号、名称、状态、等级、资质异常标记；页签依次为
概览（基本信息 + 最近 4 期绩效 + 未关闭整改单数）、联系人、资质证书、供货品类、
银行账户（仅有权角色可见）、寻源记录、价格、订单、质量、对账、风险事件、变更历史。

**寻源单工作页**（内部）：上半部分是寻源单信息与「已邀请 N 家 / 已报价 N 家」；
下半部分在开标前显示邀请与响应状态，开标后切换为比价表与比价矩阵；页头按钮随状态
变化：发布 → 开标 → 下一轮 → 提交定标。

**整改回复页**（门户）：按 8D 步骤分段显示，当前待填的步骤展开，其余折叠；逾期倒计时在
页头；SQE 的退回意见直接显示在被退回的步骤上。

**订单确认页**（门户，ERP 集成后的门户镜像）：订单头只读；订单行表格内联编辑「答复交期 /
答复数量 / 延期原因」，一个「确认全部」按钮处理交期与需求一致的常见情况。手机上表格折叠为卡片。

**报价页**（门户）：显示截止倒计时；明细表格内联填写单价、交期、税率；提交前汇总
总价；截止后整页只读并提示「已截止」。

## 4. 仪表盘与指标口径

### 4.1 指标口径

仪表盘的求和、平均只能落在存储的数值字段上，公式字段不行。所以比率的分子、分母都是存储
字段的计数或合计：交付记录上的值在**写入时**由字段表达式算好存下（02 §4.6），比率由数据集
`srm_delivery_metrics` 用两个合计之比（derived ratio）得出，不在查询时按行现算；考评单上的比率由
考评 flow 写入存储字段（v0.5）。按供应商、期间的明细见报表「供应商交付与质量（按期间）」。

| 指标 | 口径 | 数据来源（存储字段） | 计算时机 |
|---|---|---|---|
| 交付准时率 OTD | 准时交付行数 ÷ 交付行数；无承诺交期时按需求日期判定 | 交付记录 `on_time`；考评单 `otd_rate` | 交付记录写入时判定，考评时按期汇总 |
| 批次合格率 | 检验结论为合格的交付行 ÷ 已检验的交付行；让步接收计为不合格 | 交付记录 `inspection_result`；考评单 `lot_pass_rate` | 同上 |
| PPM | 不良数 ÷ 实收数 × 1,000,000 | 交付记录 `defect_quantity`、`received_quantity_mn`（实收数 ÷ 1,000,000）；考评单 `ppm` | 交付记录写入时存实收数（百万），看板取两个合计之比；考评时按期汇总 |
| 订单响应及时率 | 下发后 24 小时内被确认的订单数 ÷ 下发订单数 | 订单 `released_at`、`confirmed_at`；考评单 `ack_on_time_rate` | ERP 集成后 |
| 寻源节约额 | Σ（预算价或上次价格 − 定标价）× 定标数量 | 寻源单 `savings_amount` | 定标时 |
| 线上寻源覆盖率 | 线上定标金额 ÷ 新增定价总金额（含 ERP 中手工定价） | 寻源单 `awarded_amount` + ERP 导出数据 | 月度（v0.7） |
| 准入周期 | 准入申请从提交到批准的天数，取中位数 | 准入申请 `created_at` 与批准时间 | 批准时写 `cycle_days` |
| SCAR 按期关闭率 | 按期关闭的整改单 ÷ 到期的整改单 | 整改单 `is_overdue`、`status` | 每日扫描 |
| 采购支出 | Σ 交付金额，按供应商 / 品类 / 法人 | 交付记录 `amount`（导入表格带单价时写入） | 导入时 |
| 审核与 SCAR 关闭率 | 按期关闭的审核问题项与整改单 ÷ 到期数 | 审核问题项、整改单 `status` / `is_overdue` | 每日扫描 |
| 资质合规 | 资质异常但仍为合格状态的供应商数 | 供应商 `qualification_alert` | 每日扫描 |

### 4.2 仪表盘清单

| 仪表盘 | 读者 | 卡片 |
|---|---|---|
| 采购总览 | 采购总监、总经理 | 本年支出（按品类）、Top 10 供应商支出、寻源节约额、供应商等级分布、资质异常数 |
| 寻源 | 品类经理、寻源工程师 | 进行中寻源单（按状态）、本月定标金额、平均有效报价家数、单一来源占比 |
| 供应商 | 品类经理、SQE | 供应商按生命周期分布、30 天内到期证书数、准入申请积压、风险事件（按严重度）——v0.5 先上生命周期分布、资质异常数、黑名单数和未关闭风险事件（按严重度、按类型、高风险数），到期证书与准入积压后续补上 |
| 交付 | 采购员、品类经理 | 按月准时 / 不准时交付行数（并列柱）、上月按供应商的 OTD（交付记录计数之比）；考评单上线后加按供应商的 OTD 趋势；待确认订单数、交期风险行数在 ERP 集成后加 |
| 质量 | SQE、质量经理 | 不合格交付行、批次合格率、PPM、按供应商的 PPM 排名、不合格交付（按供应商、物料）——默认上月，可改区间（v0.4 Q1）；未关闭整改单（按状态）、逾期整改单（v0.4 Q2，看当前积压、不受日期区间过滤）；审核问题项关闭率随审核上线 |
| 门户首页 | 供应商 | 待办计数卡片、最新等级与总分、近 4 期得分趋势 |

两个平台约束会影响卡片设计：

- **比率不在查询时按行现算**：比率只取两个存储字段合计之比；月度 OTD 趋势用「准时 / 不准时」
  两组计数的柱图表达（数据集图表不能指定堆叠，画成并列柱），季度比率趋势读考评单上已存储的 `otd_rate`；
- **多值字段不能做分组维度**：按「供货品类」统计供应商数时，基于供货品类资格对象
  （每行一个品类）分组，而不是基于供应商上的多选字段。

另外，仪表盘在首次上线时可能因为数据太少而显示 0，建议一期上线先交付数据与视图，
跑满一个月后再启用趋势类卡片。

## 5. 通知

平台的 `notify` 节点只能发给组织内用户（objectstack#25444）：v0.6 前供应商侧的通知发给
内部经办人（品类经理 / SQE），由其转告；v0.6 起发给供应商的门户用户。

| 事件 | 接收人 | 通道 | 版本 |
|---|---|---|---|
| 待你审核的准入申请 | 审批人 | 站内 + 邮件 | v0.1 |
| 证书即将到期 / 已过期 | SQE（v0.6 起加供应商联系人） | 邮件 + 站内 | v0.1 |
| 银行账户变更待复核、变更已生效 | 应付会计 / 采购员 | 站内 | v0.2 |
| 合同待审批、合同即将到期 | 审批人、合同所有者、品类经理 | 站内 + 邮件 | v0.3 |
| 新整改单、整改退回、整改重开、整改逾期 | 负责 SQE（新整改单没有 SQE 时发质量经理）；逾期加质量经理（SQE 主管）；v0.6 起加供应商 `quality` 联系人 | 邮件 + 站内 / 门户待办 | v0.4 |
| 待你评分、绩效结果发布 | 评分人；采购总监（v0.6 起加供应商 `admin` 联系人） | 站内 + 邮件 | v0.5 |
| 门户邀请、准入申请已受理 / 已驳回 / 已通过 | 受邀联系人、申请联系人 | 邮件 | v0.6 |
| 新的询价邀请、报价截止前 24 小时仍未提交、中标 / 未中标、待你审批的定标 | 受邀供应商 `sales` 联系人；审批人 | 邮件 + 门户待办 | v0.7 |
| 新订单待确认、订单变更、交期风险、订单 24 / 48 小时未确认、付款完成 | 供应商 / 采购员 / 采购主管 | 邮件 / 站内 | ERP 集成后 |

通知模板统一放在应用包里，按中文 / 英文两套维护；邮件只给出摘要和门户链接，**不在
邮件正文里放报价金额、银行账号等敏感内容**。

## 6. 多语言与移动端

- **多语言**：对象、字段、选项、视图标签和通知模板按中文维护；英文翻译覆盖全部元数据，
  不只门户涉及的对象，海外工厂的内部员工和境外供应商都要能用英文界面
  （[ADR-0007](../adr/0007-china-first-with-overseas-seams.md)）。CI 用 `os i18n check --strict`
  检查，缺少英文词条即失败。选项值（机器名）不随语言变化。
- **移动端**：门户的首页待办、订单确认、整改回复、对账确认在手机浏览器可完成；比价
  矩阵、供应商 360 页等内部重度页面只保证桌面端体验。
