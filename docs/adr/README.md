# 决策记录（ADR）

记录 hotsrm 的关键设计决定：当时为什么这么定、比较过哪些方案、带来什么后果。以后有人想
改变某个决定，先读对应的记录；真要改，就写一份新的记录取代旧的，不直接改写旧记录的
「决定」部分。

| 编号 | 决定 | 状态 |
|---|---|---|
| [0001](./0001-declarative-only.md) | 只用元数据实现，不依赖应用代码 | 已采纳 |
| [0002](./0002-packs-composed-into-one-app.md) | 扩展包在构建时与核心合成一个应用 | 已采纳 |
| [0003](./0003-portal-isolation-by-supplier-position.md) | 门户按「每家供应商一个岗位」隔离 | 已采纳 |
| [0004](./0004-sealed-bid.md) | 封标：开标前内部读不到报价，截止后供应商改不了报价 | 已采纳 |
| [0005](./0005-governance-and-system-share-parameters.md) | 体系文件与系统共用一份参数，源文件用 Markdown | 已采纳 |
| [0006](./0006-single-org-with-business-units.md) | 多法人默认用单组织加业务单元树，不开墙 | 已采纳 |

## 写法

文件名 `NNNN-英文短名.md`，编号递增、不复用。每份记录包括：

- **状态**：提议中 / 已采纳 / 已被 NNNN 取代；
- **背景**：要解决什么问题，有哪些约束（引用平台文档或实测结果）；
- **决定**：一句话说清楚，再展开要点；
- **考虑过的方案**：每个方案的代价，为什么没选；
- **后果**：这个决定让哪些事变容易、哪些事变难，以及需要遵守的规则；
- **待验证**（如有）：做决定时还没验证、实现前必须确认的事。
