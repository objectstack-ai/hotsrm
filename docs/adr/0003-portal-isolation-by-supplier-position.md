# ADR-0003：门户按「每家供应商一个岗位」隔离

- 状态：已采纳
- 日期：2026-10-22

## 背景

供应商门户的用户来自互相竞争的公司，任何一家都不能看到另一家的报价、订单、绩效。门户
用户是平台组织的成员，和内部员工在同一个环境里。隔离必须满足：

- 只用元数据实现（[ADR-0001](./0001-declarative-only.md)）；
- 取不到隔离依据时一行都不放行（fail-closed）；
- 界面、REST API、导出、AI 助手各个通道都生效。

平台的 RLS 谓词能比较「记录字段」与「当前用户的上下文值」，`current_user.positions` 是
当前用户持有的岗位集合；RLS 不能跨对象引用。

## 决定

- 每家开通门户的供应商对应一个岗位 `srm_vendor_<供应商编号小写>`，挂载门户权限集；
  该供应商的门户用户都任命到这个岗位。岗位是环境级的定义，由管理员在首次开通门户时
  新建。
- 供应商档案和每张面向供应商的顶层单据都有 `portal_position` 字段，创建时由 flow 从
  供应商档案复制，门户只读；`master_detail` 子记录跟随父记录。
- 门户权限集上的 RLS 只放行 `portal_position in current_user.positions` 的行。
- 每个带 `portal_position` 的对象都有一条校验规则：值非空时必须以 `srm_vendor_` 开头，
  防止写成 `everyone` 之类的内置岗位而对全体用户可见。
- 一个寻源单要给多家供应商看，无法用单值字段表达，所以门户不读寻源单本身：发布时把
  供应商需要的信息快照到邀请和报价明细上。

## 考虑过的方案

| 方案 | 为什么没选 |
|---|---|
| 应用注册 RLS 成员集合解析器，写成 `supplier in current_user.portal_supplier_ids` | 需要应用代码，托管云不执行；保留为自托管的可选增强 |
| 记录所有者设为供应商用户 | 一家供应商有多个用户时只有所有者能看；破坏「所有者 = 内部经办人」的语义 |
| 每家供应商一个组织（多组织隔离） | 一张寻源单要同时给多家供应商看，跨组织做不到；还需要企业版许可 |

## 后果

- 每家供应商首次开通门户时，管理员要新建一个岗位；岗位数量随供应商增长。
- 新增任何面向供应商的顶层对象，都必须同时加 `portal_position`、前缀校验、门户 RLS 和
  隔离测试（[核心 04 §3.7](../design/04-security-and-portal.md#37-隔离验收测试)）。
- 内部权限集一律不设 `isDefault`：门户用户也是组织成员，默认权限集会直接作用到他们
  身上。
- 用户目录（组织成员列表）的可见范围由平台成员权限决定，不在本决定的控制范围内，
  上线前单独验证（核心 04 §3.6）。

## 待验证

- flow 能否以系统身份写岗位任命；不能时由管理员手工任命。
  - 结果（2026-10-23）：岗位本身是元数据定义，flow 不能创建，由管理员新建（objectstack
    ADR-0090 修订）；用户 ↔ 岗位任命 `sys_user_position` 是数据行，但受委托管理范围
    约束，系统身份的 flow 写入是否放行平台源码没有明确答案（objectstack#25251）。已向
    平台提交「按外部方在运行时建岗位并任命」的需求（objectstack#25443）。门户在 v0.6
    开工前按 07 §6 的 V2、V3 实测；不放行时「开通门户」screen flow 只做回填，任命由
    管理员在成员页完成。
  - 结果（2026-10-26，平台 18.1.0）：`runAs: 'system'` 的 flow 不得写岗位任命、权限集分配和邀请
    （objectstack#25251 已关）；`runAs: 'user'` 是否放行由 v0.6 U1 实测（07 §6 V2）。
- 门户用户能否列出全组织用户：实测可以（objectstack#25233，P1），与本记录的
  「用户目录可见范围不在控制范围内」一致；平台修复前不开门户。
  - 结果（2026-10-26，平台 18.1.0）：平台新增组织角色 `external`，持有者只读自己的身份行，OWD 对其一律视为
    仅本人，数据只来自持有的岗位 / 权限集上的授权和共享（objectstack#25233 已修）。门户用户按 `external` 邀请
    （核心 04 §3.3），v0.6 U1 复测。
- 平台以后若支持在元数据里声明成员集合，可以改用成员集合的写法，取消逐家建岗位。
  - 结果（2026-10-26）：18.1.0 已提供 `ObjectSchema.membershipKeys`（objectstack#25234）。是否改用由 v0.6 U2
    实测后定，改用时写新 ADR 取代本记录的相应部分（核心 04 §3.5）。
