# ADR-0001：只用元数据实现，不依赖应用代码

- 状态：已采纳
- 日期：2026-10-22

## 背景

ObjectStack 的应用可以包含两类东西：元数据（对象、字段、校验规则、权限、flow、视图等）
和代码（生命周期钩子、插件、服务端函数）。在托管云上安装应用包时，平台只合并包里的
元数据，包里声明的代码函数**不会执行**，安装时会提示「该包声明的处理函数不会在此环境
运行」。hotsrm 的主要部署方式是托管云，也要能自托管。

## 决定

hotsrm 的所有业务规则都用元数据表达，不依赖任何应用代码：

- 数据结构：对象、字段、共享选项列表、汇总字段；
- 规则：`state_machine` 与 `script` / `cross_field` 校验规则（可用 `now()`，可经一个引用
  字段读关联记录）；
- 权限：权限集、岗位、OWD、行级权限（RLS）、字段级权限；
- 自动化：flow（记录触发、定时、相对日期、`api`、`screen`）与审批节点；
- 需要跨对象判断、校验规则表达不了的写操作，只开放为以系统身份运行的 `screen` flow，
  用户对目标对象不授予直接创建权限。

需要代码才能做的增强（例如 RLS 成员集合解析器、服务端批量函数），只作为自托管部署的
可选项，单独标注，任何流程不得以它们为前提。

## 考虑过的方案

| 方案 | 为什么没选 |
|---|---|
| 用生命周期钩子实现跨对象校验和批量处理 | 托管云上不执行，规则会静默失效：安装成功、看起来正常，但规则不生效 |
| 托管云和自托管各维护一套实现 | 两套实现必然分叉，测试和文档都要翻倍 |

## 后果

- 同一个应用包在托管云和自托管上行为一致。
- 一些规则要换一种写法：冗余判断依据到本记录再校验、用 screen flow 做受控写入口、
  用追赶式扫描代替精确定时（见[核心 03 §2](../design/03-processes-and-automation.md#2-平台机制与本设计的用法)）。
- 代码评审时，任何新增的钩子、插件或函数都要说明它为什么不是业务规则的唯一保障。
