# ADR-0004：封标——开标前内部读不到报价，截止后供应商改不了报价

- 状态：已采纳
- 日期：2026-10-22

## 背景

线上询价的公正性取决于两点：截止前采购方任何人都不能看到报价（防止泄露给关系户），
截止后供应商不能再改价（防止看到风声后调价）。要求对所有角色生效，包括管理员和 AI
助手；也不能依赖定时任务准时运行，因为定时触发可能延迟或漏跑。

## 决定

**内部读不到**

- 报价单有 `bid_opened` 标志，默认 false，只有开标 flow 以系统身份置为 true。
- 内部角色读报价单的唯一通道是 RLS `bid_opened == true`，挂在寻源、高管、内控三个权限集
  上；报价明细是报价单的 `master_detail` 子对象，跟随父记录。
- 系统管理员权限集不授予报价读权限；AI 助手以提问者身份查询，同一条 RLS 生效。
- 内部仍能看到「已报价 N 家」：寻源单上的汇总字段只统计数量。

**截止后改不了**

- 发布时把寻源单的截止时间复制到 `locked_deadline` 和每张报价单上，均为只读；延期只能经
  「延期截止」screen flow 同时更新三处。
- 报价单的校验规则：`now() > record.quote_deadline && record.bid_opened == false` 且状态
  不是改为 `expired` 时拒绝写入；报价明细经一跳读取报价单做同样判断。这是**写入时**的
  检查，不依赖截标扫描是否准时。
- 寻源单的校验规则：状态进入 `bid_closed` 及以后时必须已过 `locked_deadline`，所以不能
  提前开标；寻源单状态对用户只读，只经 screen flow 推进。
- 开标后门户的写策略也不再放行（RLS 写策略要求 `bid_opened == false`），上一轮报价置为
  `superseded` 后同样不可改。

## 考虑过的方案

| 方案 | 为什么没选 |
|---|---|
| 靠截标扫描任务在截止时把报价改为只读 | 扫描可能延迟或漏跑，期间仍能改价 |
| 用字段级权限隐藏金额字段 | 报价行仍可见（供应商名单、交期、附件都会泄露），而且管理员通常不受字段级权限限制 |
| 用代码钩子在写入时比较截止时间 | 托管云不执行应用代码（ADR-0001） |

## 后果

- 截止时间以 `locked_deadline` 为准，寻源单上可编辑的 `quote_deadline` 在非草稿状态下
  必须等于它。
- 任何新增的、能读到报价的权限集或报表，都必须同样受 `bid_opened` 约束；测试要覆盖
  截止前后的界面、API、导出、仪表盘、AI 五个通道。
