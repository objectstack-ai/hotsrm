# ADR-0009：先做核心包；扩展包的准入标准与接入规则；客户个性化放客户层

- 状态：已采纳；收窄 [ADR-0002](./0002-packs-composed-into-one-app.md) 的扩展包接入规则
- 日期：2026-10-23

## 背景

- 三个行业扩展包（大宗物料、危化品、国企采购合规）已有设计，但还没有任何一个客户
  要求它们。按包开发意味着从第一天起维护「只有核心」「核心 + 单包」「核心 + 全部」
  的组合构建和测试，而这些组合没有客户验证。
- 平台是元数据驱动的，AI 能完整读懂整个应用，把一组对象从核心拆成一个包、或把客户
  需求生成为私有包，都是几天的工作。「先按包设计、再按包维护」在 AI 时代不再是省
  力的做法；真正要守住的是核心的稳定性。
- 真实客户落地时会要求改字段：标签、必填、选项、新增字段、隐藏字段。平台的
  租户 Studio 覆盖层能表达这些（objectstack ADR-0029 D9、ADR-0126「标准软件包 +
  Studio 定制」），扩展能加字段、索引、校验，但不能删除核心字段；覆盖层与包的
  删除冲突平台目前不检测（objectstack ADR-0005）。
- `objectExtensions` 给核心对象加字段后，Studio 里该对象的设计会分成「核心 +
  扩展」两层，字段不能自由重排；扩展字段过多时客户在 Studio 里难以设计。
- 2026-10-23 与田騏讨论后确认：现阶段只做基础的核心包。

## 决定

1. **先做核心包，v0.7 前不做任何扩展包**。三个扩展包的设计文档保留，状态标为
   「设计保留，未排期」，等客户出现时再决定做包还是进核心。
2. **扩展包的准入标准**（满足任一才立项为包）：
   - 受法规约束，有明确的合规要求（如国企采购合规）；
   - 三家以上客户复用同一套做法；
   - 需要保护专门的测试资产（如封标测试、安全事件流程）。
   只是一家客户的做法，不做包，放客户层。
3. **扩展包的接入规则**（在 ADR-0002 三种方式的基础上收窄）：
   - 包主要新增**自己的对象**（`srm_<前缀>_*`），用 `lookup` 关联核心对象；
   - 对核心对象的 `objectExtensions` 每个包不超过 2–3 个字段，只放关联键和开关，
     业务字段放包自己的对象；
   - **暂不做桥接模块**：两个包之间的联动等两个包都有客户时再设计；
   - 组合构建测试在第二个包出现时才加入 CI，在此之前按单个应用开发。
4. **客户个性化放客户层**，不改核心和包的源码。客户层包括：参数取值
   （`params`）、体系文件实例、Studio 覆盖层（标签、必填、选项、新增字段、隐藏
   字段、视图、流程）、AI 生成的客户私有包（客户自己的对象和流程）。规则：
   - 核心字段只能隐藏，不能删除；
   - 不改核心对象和字段的 API 名、字段类型；
   - 客户要求暴露核心设计错误时，改核心并对所有客户升级，不在客户层打补丁；
   - 核心升级前跑一次「核心 + 客户层」组合构建，补平台尚未检测的覆盖层冲突。
5. **核心 API 名冻结**：对象名、字段名、字段类型一旦合入主干就不再改；改必须附
   ADR。v0.7 结束时核心 27 个对象整体冻结（门槛 2），此后改动还要附迁移说明。
6. **中国特有的做法仍直接进核心**（维持 [ADR-0007](./0007-china-first-with-overseas-seams.md)），
   但在对象里单独分组（如供应商的「工商与税务」分组：统一社会信用代码、纳税人
   类型等），将来出现第一家全球客户时可以按边界评估 §8 的清单拆成中国本地化包。

## 考虑过的方案

| 方案 | 为什么没选 |
|---|---|
| 维持原计划：核心与三个包并行开发，每种组合都进 CI | 没有客户验证的组合，测试和文档成本先付出；核心会为包预留大量选项列表和分组 |
| 只做基础模板，每个客户完全个性化，不做任何包 | 受法规约束、多家复用的做法（国企合规）会在每个客户那里各写一遍，无法升级 |
| 大量使用 `objectExtensions` 把包的字段挂到核心对象上 | 核心对象在 Studio 里变成多层，客户难以设计；扩展字段也不能被客户删除 |

## 后果

- [ADR-0002](./0002-packs-composed-into-one-app.md) 的构建时组合机制、「只加不减」
  和三种接入方式仍然有效；桥接模块、组合测试矩阵推迟到第二个包出现。
- [AGENTS.md](../../AGENTS.md) 红线 4 按本记录收窄，并增加「核心 API 名冻结」。
- [docs/packs/](../packs/README.md) 标注「设计保留，未排期」，并写明包之间的依赖
  顺序（大宗、危化依赖 ERP 集成；国企包可以最先做）。
- 实施手册（`docs/implementation/`，待建）要写明客户层的四种定制方式和边界。
- 源语言（中文源英文译，还是英文源中文译）在 v0.3 前单独决定（计划 D4），不影响
  本记录。
