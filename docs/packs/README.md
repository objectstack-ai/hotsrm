# hotsrm 行业扩展包

> 状态：设计草案 v0.1（2026-10-22）
> 上位文档：[核心设计](../design/README.md)

## 1. 三层结构

hotsrm 面向不同行业的企业，但不为每个客户做一套系统。客户实际使用的版本由三层叠加而成：

| 层 | 内容 | 谁会用 | 放在哪里 |
|---|---|---|---|
| **通用核心** | 所有企业都需要的供应商管理功能与管理制度：供应商生命周期、寻源定价、合同、订单协同、质量整改、绩效、对账、门户 | 所有客户 | 本仓库 `docs/design/`，以及核心应用包 |
| **行业扩展包** | 某一类企业共有的做法，以独立应用包的形式叠加在核心之上 | 同类客户 | 本仓库 `docs/packs/`，以及各扩展包 |
| **客户配置** | 某个客户的参数取值、组织结构、物资目录、审批权限、文件编号与样式，以及少量专属段落 | 单个客户 | 客户的私有仓库与客户环境，**不进本仓库** |

客户提出一个新需求时，按下面的顺序决定它落在哪一层：

1. 别的客户也会需要吗？会 → 做进**通用核心**；
2. 同一类客户（同行业、同类物料、同类所有制）会需要吗？会 → 做进**扩展包**；
3. 只是取值不同吗？是 → 做成**参数**，在客户配置里赋值；
4. 以上都不是 → 才算**客户定制**。定制要尽量少，并且定期评估能否上提到前三层。

## 2. 扩展包清单

| 扩展包 | 解决什么 | 典型适用行业 | 文档 |
|---|---|---|---|
| 大宗物料包 | 年度协议与月度配额、市场价联动定价、到货计量与运输损耗、批次化验与质量奖罚、按批次结算 | 化工原料、焦化与炭材料、钢铁（矿石、废钢、合金）、电力热力（燃煤）、建材、粮油 | [bulk-materials.md](./bulk-materials.md) |
| 危化品包 | 危险化学品物料属性、供应商许可范围核验、承运商与车辆人员资质、入厂预约与卸车查验、安全事件与考核 | 化工、医药中间体、油品、涂料、电子化学品 | [hazmat.md](./hazmat.md) |

| 民营精细化工企业 | ✔ | | ✔ | |
| 以液体大宗原料为主的国有化工企业 | ✔ | ✔ | ✔ | ✔ |
| 国有装备制造企业 | ✔ | | | ✔ |

## 3. 扩展包的形态

每个扩展包同时包含**系统部分**和**制度部分**：

| 组成 | 说明 |
|---|---|
| 对象与字段 | 扩展包新增自己的对象，命名为 `srm_<包前缀>_*`（大宗物料包 `srm_bulk_`、危化品包 `srm_hz_`、国企采购合规包 `srm_soe_`），通过 `lookup` 关联核心对象 |
| 对核心对象的扩展 | 尽量不改核心对象。确需给核心对象加字段时（例如订单的来源标记），用平台的对象扩展机制，在实现前验证；不能扩展的，改为扩展包自己的关联对象 |
| 流程与自动化 | 扩展包自己的 flow、审批、screen flow；与核心流程衔接的地方写明触发点 |
| 权限 | 扩展包自己的权限集；面向供应商的对象沿用核心的门户隔离方式（`portal_position`，见[核心 04 §3](../design/04-security-and-portal.md#3-供应商门户的数据隔离)） |
| 参数 | 扩展包声明自己的参数及示例默认值；客户在私有配置里赋值 |
| 体系文件模板 | 扩展包对应的管理办法与表单模板，见 [体系文件](../governance/README.md) |
| 集成 | 扩展包需要的外部系统接口（如地磅、化验系统、电子招标平台） |

技术上，每个扩展包是一个依赖核心包的独立应用包，安装核心后按需安装。扩展包之间
不互相依赖；两个包都装时才生效的联动（例如大宗物料的到货批次关联危化品的入厂查验），
在两边都用可空的 `lookup` 表达，只装一个包时该字段为空、不影响使用。

## 4. 编写约定

- **不写客户名，也不写能认出客户的组合**：示例用行业通行做法，不照搬某个客户的物料
  清单、组织形态或合同条款。
- **参数给示例值并标明「示例」**：不使用任何客户的实际取值。
- **引用法规写名称，不抄全文**：具体适用以现行法规和客户法务意见为准。
- **与核心一致**：沿用核心的建模原则（[核心 02 §1](../design/02-domain-model.md#1-建模原则)）和
  声明式优先的约束（[核心 03 §2](../design/03-processes-and-automation.md#2-平台机制与本设计的用法)）。
