# 交付记录导入说明

> 状态：v0.4（2026-10-24）。对应 FR-601、[03 §8](../design/03-processes-and-automation.md#8-p7-交付记录导入与质量整改scar--8dv04)、
> [02 §4.6](../design/02-domain-model.md#46-质量v04)。导入用平台对象列表自带的「导入」功能，不写代码；
> 样例表格在 [`data/samples/`](../../data/samples/README.md)（`srm_delivery_record.csv`），CI 用它跑两遍验证幂等
> （[test/import-idempotency.test.ts](../../test/import-idempotency.test.ts)）；用模拟「脏」表格试导的结论见 §5。

## 1. 谁来导、什么时候导

每月初由 **SQE**（岗位 `srm_sqe` 或质量经理）把上月的收货与检验结果从 ERP（或质量系统）导出、导入
**质量 › 交付记录**。没有质量系统的客户，IQC 检验员（`srm_iqc_inspector`）在同一个对象里逐条录入。
采购员、品类经理只读。导错的行由 SRM 系统管理员删除后重导。

| 项 | 取值 |
|---|---|
| 写入方式 | 新增或更新（upsert） |
| 匹配字段 | ERP 收货单号 + ERP 订单号 + ERP 订单行号 |
| 「匹配字段为空时跳过」 | **不**勾选：缺收货单号的行要报错，不能悄悄跳过 |

先导物料（[样例说明](../../data/samples/README.md#物料-srm_materialcsv)），供应商要已经在系统里（准入建档或存量导入）。
先点「试运行」看预览，没有错误行再正式导入。

一条订单行分几次到货时，ERP 每次到货生成一张收货单，导出表格里是几行，SRM 里也是几条记录、各自判定准时。
所以匹配键里有收货单号；只按订单号 + 行号匹配，第二次到货会覆盖第一次。

## 2. 字段说明

表头用字段的中文标签，导入向导按标签对列。

| 列 | 必填 | 说明 |
|---|---|---|
| ERP 收货单号 / ERP 订单号 / ERP 订单行号 | 是 | 物料凭证号、采购订单号、订单行号，原样导出，不要去掉前导零 |
| 供应商 | 是 | 供应商全称，与 SRM 里一致 |
| 物料 | 是 | ERP 物料号（找不到时再按物料名称找）；大小写要一致 |
| 工厂 | 否 | 工厂编码（如 `P100`，找不到时再按工厂名称找） |
| 需求日期 / 实到日期 | 是 | `YYYY-MM-DD` |
| 承诺日期 | 否 | 供应商确认的交期；有它时按它判定准时 |
| 订单数量 / 实收数量 / 合格数量 | 实收数量必填 | 不能为负；合格数量、不良数不能大于实收数量 |
| 单位、金额 | 否 | 金额用于按供应商的支出分析 |
| 检验结论 | 是 | 合格 / 不合格 / 让步接收 / 未检 |
| 严重度 | 不合格时必填 | 严重 / 主要 / 次要 |
| 不良数 | 不合格、让步接收时必填 | 判批合格但抽检发现少量不良的，也填上，计入 PPM |
| 不良描述 | 否 | |

**不需要**的列：「准时」「期间」由系统按日期计算（准时 = 实到日期不晚于承诺日期，没有承诺日期按需求日期；
期间 = 实到日期的年月），表格里带了也会被忽略、重算，试运行报告里会列出被忽略的列。

## 3. 重复导入

同一张表格可以重复导入，结果一致：已存在的记录按匹配键更新，表格里的值以最新一次为准，准时与期间随日期重算。
ERP 里事后更正了检验结论或数量，把那个月重新导出再导一次即可。

## 4. 导入之后看什么

- **交付记录 › 不合格交付**：不合格与让步接收的行，按供应商分组；严重 / 主要不合格在 v0.4 Q2 起自动开整改单。
- **交付记录 › 不准时交付**、**按期间**、**按供应商**。
- **分析 › 交付看板 / 质量看板**：默认看上月；**分析 › 供应商交付与质量**按期间、供应商出 OTD、批次合格率、PPM
  （口径见 [05 §4.1](../design/05-experience-and-analytics.md#41-指标口径)：让步接收计不合格批，未检不进合格率分母）。

导入后核对：报告里「新建 + 更新」= 表格行数 − 报错行数。

## 5. 试导结果与清洗清单

### 5.1 试导

2026-10-24 用一份模拟的「脏」月度表格试导（[`data/samples/delivery-trial/`](../../data/samples/delivery-trial/srm_delivery_record.csv)，
18 行，全部虚构），逐行结果由 [test/delivery-record.test.ts](../../test/delivery-record.test.ts) 钉住。结论：

| # | 表格里的问题 | 平台的结果 | 判断 |
|---|---|---|---|
| D1 | 日期写成 `2026.10.08`、`20261008` | 整行 `invalid_date` | 平台限制，objectstack#25493；先清洗 |
| D2 | 供应商写简称、工厂写「一厂」、物料号不存在 | `reference_not_found` | 正确拦截 |
| D3 | 物料号小写 `ex-100004` | `reference_not_found`（查找区分大小写） | 平台限制，同 objectstack#25491；先清洗 |
| D4 | 物料列写的是物料名称 | 按名称找到并导入 | 正确（名称重复时报 ambiguous） |
| D5 | 检验结论写 `OK` | `invalid_option` | 选项没有别名，objectstack#25493；先清洗。带尾随空格的「合格 」能导入 |
| D6 | 不合格没写严重度、不良数；让步接收没写不良数 | `required` | 正确拦截 |
| D7 | 不良数大于实收数 | 校验规则报错 | 正确拦截 |
| D8 | 同一张表里重复的行 | 第二行 `UNIQUE_VIOLATION`，第一行正常导入 | 正确拦截 |
| D9 | 没有实到日期、没有收货单号 | `required` | 正确拦截 |
| D10 | 退货行（负数量、负金额） | `min_value` | 正确拦截；退货不在交付记录里，导出时排除 |
| D11 | 数量带千分位 `1,200` | 按 1200 导入 | 正确 |
| D12 | 表格带了「期间」「准时」两列，值是错的 | 两列被忽略，按实到日期重算 | 正确 |

没有发现把错误数据写进系统的情况：问题行要么被拒，要么按系统规则重算。

### 5.2 清洗清单

导入前在表格里逐项处理：

1. **日期**统一成 `YYYY-MM-DD`。
2. **检验结论、严重度**只用系统里的中文标签（合格 / 不合格 / 让步接收 / 未检；严重 / 主要 / 次要），把 `OK` / `NG`、
   `A` / `B` / `C` 之类的代码先换掉。
3. **物料号**与物料主数据完全一致（大小写、前导零）；**供应商**用全称；**工厂**用工厂编码。
4. **退货、冲销行**（负数量）从导出里排除；同一张收货单的同一订单行只留一行。
5. 不合格、让步接收的行补齐严重度和不良数。
