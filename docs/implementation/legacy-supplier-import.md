# 存量供应商导入说明

> 状态：v0.2（2026-10-23）。对应 [07 §4 R6](../design/07-delivery-plan.md#4-风险与应对)、
> FR-107。导入用平台对象列表自带的「导入」功能，不写代码；样例表格在
> [`data/samples/`](../../data/samples/README.md)（`srm_supplier*.csv`），CI 用它们跑两遍验证幂等
> （[test/import-idempotency.test.ts](../../test/import-idempotency.test.ts)）；用模拟「脏」台账试导的结论见 §6。

## 1. 谁来导、按什么顺序

由 **SRM 系统管理员**（岗位 `srm_admin`）导入。品类经理和 SQE 不能写「存量导入」标记，
避免绕过准入直接建「合格」供应商。三张表按顺序导入，后两张按供应商全称找供应商：

| 顺序 | 表格 | 导入到 | 写入方式 | 匹配字段 |
|---|---|---|---|---|
| 1a | 供应商 | 供应商 | 新增或更新（upsert），勾选「匹配字段为空时跳过」 | 统一社会信用代码 |
| 1b | 同一张供应商表再导一遍 | 供应商 | 同上 | 国家 / 地区 + 注册号 / 税号 |
| 2 | 联系人 | 供应商联系人 | 新增或更新 | 供应商 + 邮箱 |
| 3 | 证书 | 资质证书 | 新增或更新（**不**勾选「匹配字段为空时跳过」，让缺编号的行报错） | 供应商 + 资质类型 + 证书编号 |

供应商表导两遍：第一遍按信用代码匹配境内供应商，境外行信用代码为空被跳过；第二遍按
「国家 / 地区 + 注册号」匹配境外供应商，境内行注册号为空被跳过（[ADR-0007](../adr/0007-china-first-with-overseas-seams.md)）。
18.3.0 起平台支持按顺序的多组匹配字段（objectstack#25578），改为一遍见 hotsrm#97。

每一步先点「试运行」看预览，没有错误行再正式导入。导入可以撤销。导入前先按 §6.2 清洗表格；
「空值」设置里加上「长期」「无」「/」，台账里写「长期」的有效期按没有到期日导入。

## 2. 字段说明

表头用字段的中文标签，导入向导按标签对列。选项列填中文标签（如「中国」「生产商」
「营业执照」），布尔列填「是 / 否」，日期填 `YYYY-MM-DD`。

**供应商**：公司全称（必填）、简称、国家 / 地区（必填）、统一社会信用代码（境内必填，
18 位数字或大写字母）、注册号 / 税号（境外必填）、供应商类型、风险等级、纳税人类型、
法定代表人、成立日期、存量导入（固定填「是」）。

- **不要**放「状态」列：存量导入的供应商建档时自动为「合格」，表格里写状态会被权限拒绝。
- 境内供应商的「注册号 / 税号」留空，否则第二遍会按注册号再匹配一次。

**联系人**：供应商（填供应商全称）、姓名（必填）、职能（多个用顿号分隔，如「商务、主账号」）、
手机、邮箱（必填）、主联系人（是 / 否，每家至多一位）。

**证书**：供应商（全称）、资质类型（必填）、证书编号（存量导入时必填，匹配用）、发证机构、
生效日期、有效期至、必备资质（是 / 否）、存量导入（固定填「是」）。

- **不要**放「状态」列：证书状态由每日资质扫描按有效期计算，导入后下一次扫描把已过期的
  证书标为「已过期」；必备证书过期的供应商随即出现在「资质异常」视图。
- 表格带不了扫描件：存量导入的证书先不要求扫描件，复核时补传（证书的「存量导入缺扫描件」视图）。

## 3. 重复导入

三张表都可以重复导入，结果一致，不产生重复记录：

- 已存在的记录按匹配字段更新，表格里的资料字段以最新一次为准；
- 供应商状态、资质异常、证书状态、「存量已复核」都不在表格里，导入不会改动它们，
  导入后冻结、淘汰或复核过的供应商保持原样；
- 已经通过准入建档的供应商出现在存量表里时，只更新资料字段，不会被标记为存量导入
  （试运行报告里会列出被忽略的「存量导入」列）；
- 存量导入的供应商建档即为合格，此后全称、信用代码、注册号、法定代表人、注册资本、注册地址只能经
  信息变更单修改（[02 §4.1](../design/02-domain-model.md#41-供应商主数据)）。重复导入时这些列与系统里的值不同，
  该行报错、不更新；值相同的行照常通过。

## 4. 导入之后：复核

品类经理在 **供应商 → 存量待复核** 视图里逐家核对档案、联系人和证书，补传证书扫描件，
确认后点 **确认复核**，供应商移出该视图。

**主联系人重复** 视图列出主联系人多于一位的供应商。校验规则拒绝第二位主联系人，18.3.0 起同一张表里
同一家写了两位「是」时第二行也被拒（objectstack#25579），所以这个视图正常是空的，留作兜底；有数据时把多余的改为「否」。

## 5. 常见错误

| 报告里的错误 | 原因 | 处理 |
|---|---|---|
| 统一社会信用代码应为 18 位数字或大写字母 | 位数不对、含小写或分隔符 | 清洗后重导该行 |
| 公司全称 / 统一社会信用代码 必填 | 境内行缺信用代码 | 补齐；查不到代码的先用境外方式或暂不导入 |
| 跳过：BLANK_MATCH_KEY | 本遍的匹配字段为空（正常：另一遍会处理这一行） | 两遍都被跳过的行说明信用代码和注册号都缺，需补齐 |
| 找不到供应商 | 联系人、证书表里的供应商全称与供应商表不一致 | 统一全称后重导 |
| 供应商匹配到多条 | 两家供应商全称相同 | 先在系统里区分全称 |
| 该供应商已有主联系人 | 系统里已有主联系人，表格又给了一位 | 先在系统里改，或把表格里的改为「否」 |
| 有效期至不能早于生效日期 | 日期填反 | 核对证书原件 |
| 证书编号 必填 | 存量证书缺编号 | 补编号；营业执照填信用代码 |
| 你没有权限 | 导入人不是 SRM 系统管理员，或表格里有「状态」列 | 换人或删列 |

## 6. 试导结果与清洗清单

### 6.1 试导

2026-10-23 用一份模拟的「脏」台账试导（[`data/samples/legacy-trial/`](../../data/samples/legacy-trial/srm_supplier.csv)，
13 家供应商、12 位联系人、11 张证书，全部虚构），逐行结果由
[test/import-trial.test.ts](../../test/import-trial.test.ts) 钉住；2026-10-26 升级到平台 18.1.0、2026-11-03 升级到 18.3.0 后复测，
变化写在「判断」列。18.3.0 起重复行两行都不写（T1），所以试导先按原样导一次供应商，再按 §6.2 第 5 条去掉重复行重导，
联系人和证书在清洗后的供应商上导入。结论：

| # | 台账里的问题 | 平台的结果 | 判断 |
|---|---|---|---|
| T1 | 同一家供应商写了两行（名称带尾随空格、境外重复行） | 18.3.0 起两行都 `DUPLICATE_MATCH_KEY`、都不写，报错写明是哪几行（此前第二行 `UNIQUE_VIOLATION`、第一行建档） | 正确拦截；去掉重复行重导（§6.2 第 5 条） |
| T2 | 日期写成 `2011.07.01`、`20090615` | 18.1.0 起按日期导入（此前整行 `invalid_date`） | 正确；不再需要清洗 |
| T3 | 不存在的日期 `2018-02-30` | `invalid_date` | 正确 |
| T4 | 国家写「中国大陆」「CN」，类型写「物流」，资质写「ISO9001」「ISO 9001:2015」，存量导入写「Y」 | 18.1.0 起选项值不分大小写也能认（`CN`、`ISO9001`、`Y` 导入）；「中国大陆」「物流」「ISO 9001:2015」仍 `invalid_option` | 选项没有别名，objectstack#25582；别名先清洗 |
| T5 | 信用代码小写、带连字符、17 位 | 校验规则 / 长度报错 | 正确拦截；18.3.0 起映射里的「转大写」生效（objectstack#25491），改用见 hotsrm#97，在此之前先清洗 |
| T6 | 境内供应商缺信用代码、境外缺注册号 | 两遍都 `BLANK_MATCH_KEY` 跳过，**不报错** | 导入后核对数量（§6.2 第 6 条）；18.3.0 起可一遍导入（objectstack#25578，hotsrm#97） |
| T7 | 一行有多处错误 | 18.3.0 起失败行的 `errors` 列出全部错误（此前只报第一处） | 正确（objectstack#25582） |
| T8 | 有效期写「长期」 | 加空值设置后导入为没有到期日，扫描永不置为过期 | 正确 |
| T9 | 同一家两位主联系人在同一张表 | 18.3.0 起第二位 `rule_violation`（此前两位都导入） | 正确拦截（objectstack#25579）；「主联系人重复」视图留作兜底 |
| T10 | 同一人的邮箱大小写不同写了两行 | 建成两个联系人（匹配区分大小写），18.3.0 起第二位作为第二主联系人被拒 | 清洗时统一小写；18.3.0 起可用映射的「转小写」（objectstack#25491，hotsrm#97） |
| T11 | 一个单元格写两个邮箱、联系人没有邮箱 | `invalid_email` / `required` | 正确拦截 |
| T12 | 联系人、证书表里的供应商全称与供应商表不一致（括号全半角、少了地名） | `reference_not_found` | 正确拦截；供应商行导入失败时，它的联系人和证书也全部失败 |
| T13 | 「道路运输经营许可证」等资质清单外的证书 | `invalid_option` | 选「其他」，证书编号照填 |
| T14 | 有效期至早于生效日期、存量证书缺编号 | 校验规则报错 | 正确拦截 |
| T15 | 同一张证书写了两行（「ISO 9001」「ISO9001」） | 18.3.0 起两行都 `DUPLICATE_MATCH_KEY`、都不写（18.1.0 时两行都新建，objectstack#26133） | 正确拦截；清洗时同一张证书只留一行（§6.2 第 5 条） |

没有发现导入把错误数据写进系统的情况：问题行要么被拒、要么被跳过。T6（被跳过、不报错）是需要人工核对的一处。

### 6.2 清洗清单

导入前在表格里逐项处理：

1. **日期**用 `YYYY-MM-DD`、`YYYY/M/D`、`YYYY.MM.DD` 或 `YYYYMMDD`（18.1.0 起都能识别）；「长期」保留，靠空值设置处理。
2. **选项列**只用系统里的中文标签：国家「中国」「德国」…，类型「生产商 / 代理分销 / 服务商 / 物流商」，
   资质类型照资质清单（如「ISO 9001」，不写年份版次），清单外的写「其他」。别名（「中国大陆」「物流」）认不出。
3. **信用代码**转大写、去掉空格和连字符，检查是 18 位；境外供应商把信用代码列留空、填注册号。
4. **邮箱**统一小写，一格一个；没有邮箱的联系人先不导。
5. **供应商全称**在三张表里完全一致（括号统一用全角），同一家只留一行；同一张证书（同一供应商、资质类型、证书编号）
   也只留一行，否则重复的几行都不写（18.3.0 起报 `DUPLICATE_MATCH_KEY`）。
6. 导入后核对：供应商表的行数 = 两遍报告里「新建 + 更新」之和 + 报错行数；差额就是两遍都被跳过的行
   （缺信用代码或注册号），补齐后重导。
7. 每家只保留一位主联系人（第二位会被拒）；导入后看一眼「主联系人重复」视图。
