# 存量供应商导入说明

> 状态：v0.2（2026-10-23）。对应 [07 §4 R6](../design/07-delivery-plan.md#4-风险与应对)、
> FR-107。导入用平台对象列表自带的「导入」功能，不写代码；样例表格在
> [`data/samples/`](../../data/samples/README.md)（`srm_supplier*.csv`），CI 用它们跑两遍验证幂等
> （[test/import-idempotency.test.ts](../../test/import-idempotency.test.ts)）。

## 1. 谁来导、按什么顺序

由 **SRM 系统管理员**（岗位 `srm_admin`）导入。品类经理和 SQE 不能写「存量导入」标记，
避免绕过准入直接建「合格」供应商。三张表按顺序导入，后两张按供应商全称找供应商：

| 顺序 | 表格 | 导入到 | 写入方式 | 匹配字段 |
|---|---|---|---|---|
| 1a | 供应商 | 供应商 | 新增或更新（upsert），勾选「匹配字段为空时跳过」 | 统一社会信用代码 |
| 1b | 同一张供应商表再导一遍 | 供应商 | 同上 | 国家 / 地区 + 注册号 / 税号 |
| 2 | 联系人 | 供应商联系人 | 新增或更新 | 供应商 + 邮箱 |
| 3 | 证书 | 资质证书 | 新增或更新（**不**勾选「匹配字段为空时跳过」，让缺编号的行报错） | 供应商 + 资质类型 + 证书编号 |

供应商表导两遍：第一遍按信用代码匹配境内供应商，境外行信用代码为空被跳过；第二遍按
「国家 / 地区 + 注册号」匹配境外供应商，境内行注册号为空被跳过（[ADR-0007](../adr/0007-china-first-with-overseas-seams.md)）。
平台一次导入只能用一组匹配字段，已提需求 objectstack#25476；支持后改为一遍。

每一步先点「试运行」看预览，没有错误行再正式导入。导入可以撤销。

## 2. 字段说明

表头用字段的中文标签，导入向导按标签对列。选项列填中文标签（如「中国」「生产商」
「营业执照」），布尔列填「是 / 否」，日期填 `YYYY-MM-DD`。

**供应商**：公司全称（必填）、简称、国家 / 地区（必填）、统一社会信用代码（境内必填，
18 位数字或大写字母）、注册号 / 税号（境外必填）、供应商类型、风险等级、纳税人类型、
法定代表人、成立日期、存量导入（固定填「是」）。

- **不要**放「状态」列：存量导入的供应商建档时自动为「合格」，表格里写状态会被权限拒绝。
- 境内供应商的「注册号 / 税号」留空，否则第二遍会按注册号再匹配一次。

**联系人**：供应商（填供应商全称）、姓名（必填）、职能（多个用顿号分隔，如「商务、主账号」）、
手机、邮箱（必填）、主联系人（是 / 否，每家至多一位）。

**证书**：供应商（全称）、资质类型（必填）、证书编号（存量导入时必填，匹配用）、发证机构、
生效日期、有效期至、必备资质（是 / 否）、存量导入（固定填「是」）。

- **不要**放「状态」列：证书状态由每日资质扫描按有效期计算，导入后下一次扫描把已过期的
  证书标为「已过期」；必备证书过期的供应商随即出现在「资质异常」视图。
- 表格带不了扫描件：存量导入的证书先不要求扫描件，复核时补传（证书的「存量导入缺扫描件」视图）。

## 3. 重复导入

三张表都可以重复导入，结果一致，不产生重复记录：

- 已存在的记录按匹配字段更新，表格里的资料字段以最新一次为准；
- 供应商状态、资质异常、证书状态、「存量已复核」都不在表格里，导入不会改动它们，
  导入后冻结、淘汰或复核过的供应商保持原样；
- 已经通过准入建档的供应商出现在存量表里时，只更新资料字段，不会被标记为存量导入
  （试运行报告里会列出被忽略的「存量导入」列）；
- 存量导入的供应商建档即为合格，此后全称、信用代码、注册号、法定代表人、注册资本、注册地址只能经
  信息变更单修改（[02 §4.1](../design/02-domain-model.md#41-供应商主数据)）。重复导入时这些列与系统里的值不同，
  该行报错、不更新；值相同的行照常通过。

## 4. 导入之后：复核

品类经理在 **供应商 → 存量待复核** 视图里逐家核对档案、联系人和证书，补传证书扫描件，
确认后点 **确认复核**，供应商移出该视图。

**主联系人重复** 视图列出主联系人多于一位的供应商。单行导入时校验规则会拒绝第二位主联系人，
但同一张表里同一家供应商写了两位「是」时规则拦不住（平台限制，objectstack#25477），
在这里把多余的改为「否」。

## 5. 常见错误

| 报告里的错误 | 原因 | 处理 |
|---|---|---|
| 统一社会信用代码应为 18 位数字或大写字母 | 位数不对、含小写或分隔符 | 清洗后重导该行 |
| 公司全称 / 统一社会信用代码 必填 | 境内行缺信用代码 | 补齐；查不到代码的先用境外方式或暂不导入 |
| 跳过：BLANK_MATCH_KEY | 本遍的匹配字段为空（正常：另一遍会处理这一行） | 两遍都被跳过的行说明信用代码和注册号都缺，需补齐 |
| 找不到供应商 | 联系人、证书表里的供应商全称与供应商表不一致 | 统一全称后重导 |
| 供应商匹配到多条 | 两家供应商全称相同 | 先在系统里区分全称 |
| 该供应商已有主联系人 | 系统里已有主联系人，表格又给了一位 | 先在系统里改，或把表格里的改为「否」 |
| 有效期至不能早于生效日期 | 日期填反 | 核对证书原件 |
| 证书编号 必填 | 存量证书缺编号 | 补编号；营业执照填信用代码 |
| 你没有权限 | 导入人不是 SRM 系统管理员，或表格里有「状态」列 | 换人或删列 |
