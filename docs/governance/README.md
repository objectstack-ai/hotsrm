# hotsrm 体系文件（管理制度）模板

> 状态：设计草案 v0.1（2026-10-22）。本文规定模板的结构、参数和生成方式；模板正文按 §6 的计划陆续补齐。

## 1. 为什么要有体系文件模板

客户上 SRM 时，通常会要求先把供应商管理制度定下来，再按制度配置系统。如果制度和
系统各写各的，很快就会出现「制度说 3 天、系统配 5 天」「制度要求双人复核、系统只有
一级审批」这样的不一致，内审和外审都会开不符合项。

hotsrm 把管理制度和系统放在一起维护：

- **每条控制要求对应一个系统控制点**：制度里写「在 SRM 系统中执行」的要求，系统一定
  有对应的控制；系统里的每个强制控制，也都能在制度里找到条款依据；
- **参数只维护一处**：审批金额档、整改时限、绩效等级线、证书提醒天数等，写在一份参数
  文件里，同时用于生成制度文本和配置系统；
- **模板通用、实例私有**：本仓库只放通用模板和示例参数；某个客户的参数取值、部门
  名称、文件编号、样式模板和专属段落，放在该客户的私有仓库里。

## 2. 文件层级

| 层级 | 类型 | 说明 |
|---|---|---|
| 一级 | 质量手册（管理手册） | 客户已有，不由 hotsrm 提供；在「外部提供的过程、产品和服务的控制」相关章节引用二级文件 |
| 二级 | 程序文件 | 规定过程的职责、程序和控制要求 |
| 三级 | 管理办法 / 作业指导书 | 规定具体业务的方法、标准和参数 |
| 四级 | 记录表单 | 与系统单据一一对应；系统上线后以系统记录为准 |

## 4. 模板与参数的格式

模板正文用 Markdown 编写，放在本仓库：

```
docs/governance/
├── README.md                     本文
├── params.yaml                   参数定义与示例默认值（核心 + 各扩展包）
└── templates/
    ├── core/                     QP-01 … GL-10
    └── packs/
        ├── bulk-materials/
        ├── hazmat/
        └── soe-procurement/
```

模板里用三种标记：

| 标记 | 含义 | 示例 |
|---|---|---|
| `{{param.<键>}}` | 引用参数值 | 整改临时措施时限 `{{param.scar_containment_hours}}` 小时 |
| `{{org.<键>}}` | 引用客户的组织信息 | `{{org.company_name}}`、`{{org.dept.procurement}}` |
| `<!-- pack:<包名> -->` … `<!-- /pack -->` | 只在安装了该扩展包时保留的段落 | 大宗原料的准入要求 |

参数定义的每一项包括：键、中文名、单位、示例默认值、使用它的文件与条款、对应的系统
配置位置。例如：

```yaml
scar_containment_hours:
  label: 整改临时措施提交时限
  unit: 小时
  example: 72
  used_in: [QP-01 6.8.2, GL-07]
  system: srm_quality_issue.containment_due 的计算规则
```

## 5. 客户实例与生成方式

客户的私有仓库只放与 hotsrm 不同的部分：

```
<客户私有仓库>/
├── org.yaml            公司名称、部门名称、文件编号规则
├── params.yaml         参数取值（覆盖 hotsrm 的示例默认值）
├── packs.yaml          启用的扩展包
├── overrides/          个别条款的专属表述（尽量少）
├── reference.docx      客户的 Word 样式模板（字体、页眉页脚、文件控制表）
└── build/              生成的 Word / PDF（交付物）
```

生成与评审流程：

1. 用 hotsrm 模板 + 客户的 org、params、packs、overrides 生成 Markdown，再用 pandoc
   按客户的 `reference.docx` 转成 Word；文件控制表、修订记录由脚本填入；
2. 把 Word 发给客户评审，客户在 Word 里批注或修订，不需要学习 git；
3. 客户的意见由实施顾问合并回参数文件或专属段落，重新生成；
4. 定稿后客户签批，**受控版本是签批后的 PDF 或 Word**；以后修订仍改源文件，每次修订
   对应一次提交，文件里的修订记录可以从提交历史生成；
5. 参数文件中的取值同时用于配置客户环境里的 SRM，保证制度与系统一致。
